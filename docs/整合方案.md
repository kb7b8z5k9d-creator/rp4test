- **结构**：基线 B + 三个零部件 C1/C2/C3 + 一条隔离实验线 E。

## 1. 目标与边界

### 目标

在 Retroid Pocket 4 Pro（Mali-G77 MC9，Android 13，原厂 Vulkan 1.1.177）上，得到一套：

- 自己能从源码编译
- 自己签名、独立包名
- 能在实机运行 Steam 和 PC 游戏
- 能持续同步上游
- 每个改动都可回退

的 DroidDeck 定制版。

### 边界

- 只针对 RP4 Pro，不为其他 Mali 机型做兼容承诺。
- 不 Root、不刷机、不修改设备分区、不卸载用户现有应用。
- 不覆盖其他开发者签名的 APK。
- Steam 登录凭据由用户本人输入，不读取、不导出、不上传。
- PanVK/DX12 只做隔离实验，不作为第一阶段验收要求。
- 不为通过启动检测伪造 Vulkan 版本或特性。

## 3. 包名、签名与更新通道

| 线 | 包名 | 显示名 |
|---|---|---|
| 主线（B → C1 → C2 → C3） | `com.rp4pro.droiddeck.lab` | RP4Pro Lab |
| E PanVK | `com.rp4pro.droiddeck.lab.panvk` | RP4Pro Lab PanVK |

规则：

- 主线 B/C1/C2/C3 **共用同一个包名**，覆盖升级：应用数据、Linux 运行时、Steam 登录状态都保留，不需要每次重新初始化或重新登录。
- 每个版本的 APK 都留档；回退时用旧 APK 覆盖安装（同签名；必要时 `adb install -r -d` 允许降级）。
- 只有 PanVK 实验用独立包名，避免污染主线；它需要单独初始化，代价可接受。
- 如果某次需要严格 A/B 同时安装，可临时用第二个包名，接受重新初始化。
- 所有线共用同一个自建签名（`keystore/lab-release.jks`，不提交仓库）。
- 包名都不以 `.mali` 结尾，因此更新通道为空，不会自动安装任何上游版本。
- 版本号保持单调递增，确保同包名覆盖安装。
- 公开的 `testkey.p12` 只用于对照测试，不作为正式签名。

## 4. 分层方案

### B 基线（P0）

**目的**：证明本机可以完整复现 fix43 的构建，并在 RP4 Pro 上跑通 Steam。

**操作**：

1. 完整克隆 `source` 分支，checkout `684939c5`。
2. 不执行 `git submodule update`（MaliBridge 已内嵌，`.gitmodules` 只是遗留）。
3. 只改包名为 `com.rp4pro.droiddeck.lab`、显示名 `RP4Pro Lab`、签名换自建、更新通道置空。
4. 用 `tools/build_local.sh` 构建 debug 与 release 各一份。
5. 记录 APK 的 SHA256、包名、签名指纹、源码提交、构建日志。

**构建环境**：

- WSL2 + Ubuntu 24.04
- Docker Desktop，镜像 `droiddeck-local-cross:24.04-v3`
- JDK 17、Android SDK（platforms 36 / build-tools 36.1 / NDK）
- `curl`、`tar`、`zstd`、`shasum`、`unzip`、`python3`、`gh`

**验收**：

- APK 能安装，包名正确，签名正确
- 应用能启动，Steam 运行环境能启动
- 游戏模式正常显示，手柄和音频可用
- 至少运行一款用户实际拥有的轻量游戏
- 退出后能再次启动，无异常崩溃

**回退**：保留一个未改动的 `base-684939c5` 标签或分支，任何改动都能 diff 回去。

### C1 MaliBridge v0.5.4.2（P1）

**目的**：吸收官方 v0.5.4.2 相对 v0.5.4.1 的有效改进，同时保留 yujikaido 的 G77 修复。

**来源**：

- `ASEbrahim/MaliBridge`，`main` 提交 `95a1e600a51299294e06bb09db2db8cc509fe6a3`，Release `v0.5.4.2`
- PR #35 仍 open、未合并，但其 `nan_position` 等修复已经在基线内嵌副本里

**方法：三方合并，不整包覆盖**

1. 取官方 `v0.5.4.1` 到 `v0.5.4.2` 的 diff（上游增量）。
2. 取基线内嵌副本与官方 `v0.5.4.1` 的 diff（yujikaido 补丁）。
3. 两份 diff 叠加，冲突处逐项人工判断，优先保留基线已验证的行为。

**必须检查**：

- v0.5.4.2 是否已自行吸收 G77 的 `mutable-format` / AHB / `nan_position` 修复
- 同一问题是否出现两套实现
- 新增代码是否依赖更高版本 Vulkan 或 Android API

**验收**：基线全部测试通过，且至少一项有可测量改善；若只是版本号变化、没有实际收益，则不做整合。

**回退**：独立分支 `lab/mali-0542`，不合并回 B。

### C2 DroidDeck 官方补丁（P2）

**目的**：从官方 main 提取对 RP4 Pro 有实际价值的通用修复。

**来源**：`Droid-Deck/DroidDeck` `main`，核对时为 `d1bd23df161de27520e05601f0ad71ab45f78a2c`（2026-10-29），后续以实际操作为准。

**方法**：

1. 完整克隆官方仓库，找到基线与官方的 `merge-base`。
2. 只审查 `merge-base` 之后、与运行相关的提交。
3. 按功能域分批移植，每批独立编译、独立测试：
   - 第一批：FEX / Proton 稳定性、进程生命周期
   - 第二批：内存与资源回收（lmkd、ION、低内存）
   - 第三批：Gamescope 与图像共享
   - 第四批：控制器、音频、休眠恢复
   - 第五批：日志与崩溃诊断
4. 普通 UI、商店、前端功能不移植。

**注意**：

- 官方 main 不含 MaliBridge 源码，G77 修复不在主仓库。
- 基线可能已包含部分官方补丁，移植前先确认。
- 若某补丁依赖多个较新组件，先评估依赖链，不强行拆出。

**记录**：每个补丁一行，含来源 commit、改动文件、解决的问题、基线是否已有、测试结果、回退方式。

### C3 The412Banner Gamescope 组件（P2/P3）

**目的**：尝试其 Gamescope 构建对 G77 图像共享的改进。

**来源**：`The412Banner/droiddeck-nonadreno-drivers` 的 Release 资产，例如 `gamescope-3.16.29-p23-nonadreno`（2026-10-27，`gamescope.tzst`）。

**性质**：这是预编译二进制包，不是源码补丁；该仓库目前不发布 APK。

**方法**：

1. 记录组件的 tag、文件名、SHA256、来源链接。
2. 替换基线自带的 gamescope，做 A/B 对比。
3. 保留基线版本，随时可回退。
4. 只替换 gamescope 一个组件，不动 MaliBridge 和其他环境。

**验收**：至少一项可观察改善（启动成功率、闪烁、伪影、帧率）且无回归；否则不纳入。

### E PanVK 实验（P4，隔离）

**目的**：验证 Linux 侧 PanVK 能否绕过原厂 Vulkan 1.1 的限制。

**来源**：

- `faux123/panvk-faux123-driver-rp4pro`，Release `v1.1.2`（Android 驱动包 `.adpkg.zip`）
- Linux 侧还需要匹配的 PanVK runtime 驱动；历史测试中的 `PanVK-Mali-kbase_Linux_glibc_` 仍卡在 ION/KBASE

**规则**：

- 独立分支 `lab/panvk`、独立包名 `com.rp4pro.droiddeck.lab.panvk`。
- 不并入稳定线，不影响 B/C1/C2/C3 的验收。
- Android 的 `.adpkg.zip` 不能直接当 Linux 驱动使用。
- 先确认是否存在与 v1.1.2 匹配的 Linux 侧驱动；没有就只做 Android 侧验证（如 Eden），不构成 DroidDeck 方案。
- 如果结构性问题无法解决，允许结项，保留已成功部分。

### 第一阶段：工程可复现

- 能从源码构建 APK
- 独立包名
- 不覆盖用户已有应用
- 签名校验通过
- 有明确 commit 和构建日志

### 第二阶段：RP4 Pro 基线

- ADB 正确识别设备
- 应用启动，Steam 运行环境启动
- 游戏模式正确显示
- 手柄、声音可用
- 至少一款用户拥有的游戏可运行
- 无异常崩溃或明显资源泄漏

### 第三阶段：整合成果

- 保留已验证的 G77 修复

- 证明新补丁没有破坏基线
- 至少一组可复核的前后对比

### 第四阶段：维护能力

- 能重复构建
- 能升级 MaliBridge
- 能识别官方后续可移植补丁

- 能方便回退
- 不需要每次手工拼接 APK

## 8. 已知风险与待验证

1. **MaliBridge v0.5.4.2 与基线内嵌 v0.5.4.1 的差异未知**：可能已吸收部分 G77 修复，也可能引入新回归。
2. **官方 DroidDeck 与基线分叉较深**：merge-base 之后可能有大量提交，需要筛选。
3. **The412Banner 组件兼容性未知**：gamescope 是预编译二进制，ABI 和配套运行时需要核对。
4. **PanVK Linux 侧配对未知**：v1.1.2 是 Android 驱动包，Linux runtime 是否存在匹配版本尚未确认。
5. **构建环境未就绪**：WSL2 虚拟机平台未启用，Docker 未安装。
6. **包名/签名改动可能影响**：Steam 启动、Android Provider、更新逻辑、存档路径。
7. **8 GB 内存与 Android lmkd**：长时间运行可能被杀进程，需要观察。
8. **Vulkan 1.1 的真实能力**：DXVK/VKD3D 对特性有要求，不能把版本号当能力。
